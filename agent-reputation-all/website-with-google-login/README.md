# Agent Reputation (self-hosted)

The same app as the claude.ai version, packaged to run in any browser (laptop, phone, Chrome, Safari, Firefox, Edge) with **real Google sign-in** and a **device-only Admin screen** that shows changes made on other devices.

```
agent-reputation-selfhost/
├── server.js            Express server: Google token check, signed login cookie, activity log API
├── package.json
├── .env.example         Copy to .env and fill in
├── data/                activity.json is created here
└── public/
    ├── index.html       The app
    ├── selfhost.js      Connects the app to server.js
    └── (config.js is generated by the server)
```

## 1. Create a Google client ID (about 5 minutes)

1. Open https://console.cloud.google.com/ and create or choose a project.
2. Go to **APIs & Services → OAuth consent screen**. Choose **External**, fill in the app name and your email, save.
3. Go to **APIs & Services → Credentials → Create credentials → OAuth client ID → Web application**.
4. Under **Authorized JavaScript origins** add every address you will open the app from, for example:
   - `http://localhost:3000`
   - `https://your-domain.com`
5. Create it and copy the **Client ID**.

## 2. Run it

Needs Node.js 20.6 or newer.

```bash
cp .env.example .env     # then edit .env: GOOGLE_CLIENT_ID, SESSION_SECRET, ADMIN_EMAIL
npm install
npm start
```

Open http://localhost:3000, tap the profile button, choose **Log in** and tap **Continue with Google**.

## 3. Admin (only on one device)

1. Put your own Google email in `ADMIN_EMAIL`.
2. Sign in with that Google account.
3. Open the left menu, find **Admin**, and tap **Enable admin on this device**.
4. Open **Changes from other devices** to see what other signed-in people did on other devices.

Only the account in `ADMIN_EMAIL` can enable it, and the switch is stored in that browser only. Other browsers and devices never show the Admin section, and the server refuses to return the log to anyone else.

## How sign-in is secured

- Google returns a signed ID token. `server.js` verifies it with Google's library (signature, audience and verified email) before trusting it.
- The server then sets a signed, HttpOnly, SameSite cookie. The page never sees a password or token it could leak.
- Deploy over **HTTPS** and set `NODE_ENV=production` so the cookie is marked Secure.

## Notes

- Email and password accounts still work, but they live only in that browser (the password is hashed there, not on the server).
- Agents, tasks and the ledger are stored per browser. Only the activity log (who did what, and when) is shared through the server.
- The activity log is a JSON file, which is fine for a small team. Use a real database for heavier use.
- "Continue with Claude" is hidden here because it only exists on claude.ai.
